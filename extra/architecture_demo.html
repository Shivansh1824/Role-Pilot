The True Multi-Voice Architecture

How we achieve a perfectly synchronized, 3-person AI interview panel with zero overlapping voices and a unified memory.

❌ The Problem with Default AI Agents

If you put 3 independent AI agents in a room, they act like 3 people wearing noise-canceling headphones. They don't share memories, they waste tokens by thinking separately, and when the candidate speaks, they all try to answer at the exact same time.

✅ Our Solution: The "Puppeteer" Architecture

Instead of 3 separate brains, we use One Central Brain (Gemini) controlling 3 "Dumb" Voice Bodies (Agora). Here is how it flows in real-time:

1. The Ears & Mouth (Agora Cloud)

The candidate speaks. Agora instantly translates the audio to text (STT). Because there are 3 agents in the room, Agora sends 3 identical text transcripts to our server at the exact same millisecond.

2. The Barrier (Next.js LLM Router)

Our Custom LLM API Route acts as a traffic controller. It receives all 3 requests but intentionally "holds" them. Using a lightning-fast In-Memory Global Map, it deduplicates the requests so we don't process the same sentence three times.

3. The Brain (Gemini Flash)

Our server makes one single, highly efficient call to Gemini. Gemini reads the transcript, applies our Prompt Engineering rules (like the Hit Counter and Verbal Handoffs), and decides who should speak next (e.g. Maya).

4. The Puppet Strings (Audio Routing)

Our server now has 3 HTTP connections waiting for an answer. It sends the AI text exclusively down Maya's connection. It explicitly returns a blank/silent response to David and Alex's connections. Result? Maya speaks, and the other two stay perfectly quiet.

1. The Hackathon Problem Statement & Core Dilemma

EchoSphere: Agora Conversational AI Hackathon — PS11: Adaptive Voice Interview Platform with Multi-Role AI Panel

Problem & Solution

Fatal Trap 1: Voice Collision (Cacophony)

If you connect 3 independent voice agents to an Agora WebRTC channel, all 3 hear the candidate finish speaking at the same millisecond. Each triggers speech synthesis, causing all 3 bots to speak over each other simultaneously in an unintelligible disaster.

Fatal Trap 2: 3x Token Burn & Desync

Running 3 independent LLM instances triples inference latency and costs 3x API tokens. Worse, each bot hallucinates independently, with no shared memory of what the other interviewers previously asked or evaluated.

Fatal Trap 3: The "Statue" Dilemma

Conventional voice bots lock audio playback until a long response is fully spoken. If the candidate attempts to interject, clarify, or answer early, the bot bulldozes forward, completely ruining conversational naturalness.

The Role-Pilot Breakthrough: The "Puppeteer" Architecture

Instead of 3 separate brains, Role-Pilot decouples the Intelligence Layer from the Voice Bodies. We use One Central Brain (Gemini 3.5 Flash) managing Three Agora WebRTC Voice Bodies via a server-side Single-Flight Concurrency Mutex. A single inference decision determines which panelist speaks, while our audio demultiplexer mutes the other two at the protocol level. Result: 0% overlap, 66.7% token savings, and unified conversational context.

2. High-Level Flow & The Nova Specialist

How the candidate transitions from 1-on-1 voice onboarding with Nova into the 3-interviewer panel room

Onboarding & STT

In Role-Pilot, "Nova" plays a vital dual role: she is both our Dedicated 1-on-1 Voice Onboarding Specialist and the high-accuracy Deepgram Nova-3 Speech Recognition Engine powering all live transcription.

Nova: 1-on-1 Onboarding Lead (/api/invite-setup-agent)

Before entering the high-stakes panel, candidates chat 1-on-1 with Nova in gear-up.html. Isolating onboarding from the panel keeps the panel's conversation history completely clean.

  • Hardware Calibration: Tests mic input, verifies audio levels, and ensures smooth WebRTC uplink.
  • Compound Utterance Parsing: If candidate says "I'm Shivansh with 3 years experience targeting Senior Backend", Nova parses name, tier, and role in 1 shot without re-asking.
  • ASR Typo Resilience: Gracefully tolerates phonetic artifacts (e.g., "devops", "pyhton", "midlevel") without rejecting the candidate.
  • Panel Track Matching: Automatically routes to Tech (Alex, Maya, David), Product, Sales, or HR panel.
  • Resume Fact-Sheet Ingestion: Ingests resume facts into a grounded 300-word fact-sheet injected directly into the panel's system prompt.

Nova-3: Cloud Streaming STT (Agora Conversational AI)

Every agent in our platform (Nova + Alex + Maya + David) is configured with Deepgram Nova-3 STT: new DeepgramSTT({ model: 'nova-3', language: 'en' }).

  • Sub-200ms Streaming Latency: Transcribes conversational audio packets in real-time as words are spoken.
  • Domain Technical Vocabulary: High accuracy on complex tech terms (Kubernetes, PostgreSQL, LRU eviction, WebRTC).
  • Accent & Dialect Normalization: Robust global phonetic acoustic models minimize word error rate (WER).
  • Cloud Native Integration: Directly streams into Agora's media gateway without roundtrip server hops.

4. How We Are Blocking: The In-Memory Single-Flight Mutex

Preventing race conditions and token waste when 3 Agora agents send concurrent HTTP requests

Concurrency & Mutex

The Challenge: Because David, Alex, and Maya are all active in the Agora room, when the candidate stops speaking, Agora Cloud dispatches 3 simultaneous HTTP POST requests to our /api/llm-router within 10–30ms of each other. If unmanaged, this triggers 3 separate Gemini calls, wasting tokens and causing divergent answers.

voice-engine/app/api/llm-router/route.ts (Single-Flight Barrier) TypeScript 
// In-Memory global state keyed by channel (persisted across requests)
const globalState = globalThis as {
  activeTurns: Map<string, { promise: Promise<string>; timestamp: number }>;
};

export async function POST(request: NextRequest) {
  const channel = url.searchParams.get('channel');
  const agentName = url.searchParams.get('agent'); // 'David' | 'Alex' | 'Maya'
  const now = Date.now();
  let turn = globalState.activeTurns.get(channel);

  // 1. MUTEX CHECK: Only trigger a new LLM call if no active turn in last 2000ms
  if (!turn || now - turn.timestamp > 2000) {
    // First agent request locks the mutex and starts the ONE shared Gemini call
    const geminiPromise = ai.models.generateContent({
      model: 'gemini-3.5-flash',
      contents: geminiContents,
      config: { systemInstruction: systemMessage, temperature: 0.7 }
    }).then(res => res.text || '');

    turn = { promise: geminiPromise, timestamp: now };
    globalState.activeTurns.set(channel, turn);
  }

  // 2. BLOCKING: Requests 2 and 3 arrive ~15ms later and await the EXACT SAME promise!
  const geminiText = await turn.promise;
...
1. Mutex Lock (t = 0ms)
First request (e.g. David) arrives, instantiates the Gemini promise, and stores it in the global Map.
2. Piggyback Wait (t = 15ms)
Requests from Alex & Maya detect active turn < 2000ms. They do NOT invoke Gemini; they await the active promise.
3. Unified Wakeup (t = 380ms)
When Gemini finishes, all 3 requests wake up with identical content. Token waste is cut by exactly 66.7%!

5. How We Avoid Overlapping Voices: Selective Demultiplexing

Eliminating audio collision at the protocol layer via speaker tag demuxing

Zero-Overlap Floor Control

Even with a single Gemini response, we still have 3 open HTTP connections from Agora. If all 3 connections return the generated text, all 3 agents will invoke MiniMax TTS and speak in chorus. Here is how we guarantee strictly zero overlap:

Selective Demultiplexer Logic in /api/llm-router TypeScript 
// System prompt mandates bracketed speaker tags: e.g., "[Maya (Product Manager)] What metrics..."
let responseText = '';
const match = geminiText.match(/^\[([^\]]+)\]\s*([\s\S]*)$/);

if (match) {
  const speakerTag = match[1];      // "Maya (Product Manager)"
  const messageContent = match[2];  // "What metrics did you track?"

  // ROUTING DECISION: Only the agent matching the speaker tag gets the text!
  if (speakerTag.toLowerCase().includes(agentName.toLowerCase())) {
    responseText = messageContent;  // Maya receives speech payload
  } else {
    responseText = '';              // David and Alex receive EMPTY STRING
  }
}

// Return standard OpenAI format expected by Agora CustomLLM
return NextResponse.json({
  choices: [{ message: { role: 'assistant', content: responseText } }]
});
Protocol Magic: Why Empty String Guarantees Silence
When Agora Cloud receives content: "" for David and Alex, its internal TTS pipeline (MiniMax) generates zero audio frames. The WebRTC RTP audio streams for David and Alex remain 100% silent. Only Maya's MiniMax TTS generates audio packets. Audio overlap is mathematically impossible.

6. What Happens If a Person Interrupts: 160ms Hardware Barge-In

How Role-Pilot achieves natural conversational turn-taking when a candidate speaks while an interviewer is talking

Barge-In Interruption

In real human interviews, candidates frequently clarify, say *"Excuse me"*, or begin answering before the interviewer finishes their thought. Role-Pilot configures Agora's native Voice Activity Detection (VAD) to handle interruptions within 160 milliseconds:

Hardware VAD Turn Detection Config (invite-agent/route.ts) TypeScript 
turnDetection: {
  config: {
    speech_threshold: 0.5,
    start_of_speech: {
      mode: 'vad',
      vad_config: { interrupt_duration_ms: 160, prefix_padding_ms: 300 }
    },
    end_of_speech: {
      mode: 'vad',
      vad_config: { silence_duration_ms: 1800 }
    }
  }
}
1
Candidate Starts Speaking (t = 0ms)
While Alex is speaking, the candidate begins talking (e.g., "Actually, before moving to Redis, let me clarify..."). Audio enters the candidate's mic.
2
160ms Hardware VAD Trigger (t = 160ms)
Agora's audio processing engine detects sustained human voice exceeding speech_threshold: 0.5 for 160ms. It immediately fires the start_of_speech interruption signal.
3
Instant Downlink Audio Flush & TTS Abort (t = 180ms)
Agora's Media Gateway immediately drops all queued audio packets in the downlink buffer and aborts Alex's MiniMax speech generation. The candidate hears Alex stop talking instantly without lag.
4
Prefix Padding & Conversational Adaptation (t = 1960ms)
Our prefix_padding_ms: 300 retroactively captures the opening syllable so no speech is clipped. After 1800ms of silence, the candidate's full clarification is packaged and sent to Gemini. Gemini smoothly acknowledges the interjection ("Sure, go ahead and clarify that first") and seamlessly continues!
